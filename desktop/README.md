# Homecoming (desktop)

Homecoming is a Mac app that walks you through collecting your whole corpus: setup, every source on this Mac, the iPhone backup, every web export, and the things only you can do, until everything available is in `corpus/`.

```bash
cd desktop
npm ci
npm start
```

To walk through it as a new person would, without touching your corpus:

```bash
npm run fresh              # start, or continue the last fresh run
npm run fresh -- --reset   # start over
npm run fresh -- --delete  # remove it
```

The fresh run reads this Mac's real sources but writes only to `~/Library/Application Support/Homecoming (fresh run)/`: its own corpus, app state and browser sign-ins, a `Downloads/` folder it watches, and `Your exports/`, holding instant APFS clones of every export already in `corpus/imports/`. Move a clone into its `Downloads/` (or drop it on the window) to play "the export email arrived". Its iPhone step checks the backup password and reuses the last iLEAPP run (`--skip-ileapp`), so it takes minutes and leaves the shared iLEAPP results alone. The window shows a "Fresh run" badge.

It uses the connectors in `../connectors/` as they are and writes the same `corpus/` (`CORPUS_DIR` overrides it, as it does for the connectors).

## What you see

The first launch opens the Setup Assistant on a welcome page: what Homecoming is for, then its three steps (request your data, bring it home, explore it), each played on made-up data: the app's own rows, then the real Explore page browsed by a pointer, then an Ask answer (`src/renderer/welcome.tsx`; the data is `src/renderer/examples.ts`, and Explore given it fetches nothing and opens no record). Clicking in the Explore window hands it to you.

After that, one list, sorted by what to do next, with details on the right.

- **Next up**: the single most useful thing to do now. Setup first (Full Disk Access, who you are), then anything time-sensitive (a download that's ready, a file found in Downloads), then the iPhone password, then web exports with the longest waits first, so their clocks start early.
- **To Do / In Progress / Collected**: each source lives in the section for its stage (not started; started and not finished, stuck or not; in the library), which only moves forward. Whether it needs you is a flag on it, not a place: a source blocked on you (Claude waiting for a sign-in, an export that's ready, a failed import) keeps its place, with an orange dot, and **To Do** lists every one of them first, under Needs you now, saying where each lives; then what hasn't started, what waits on a setup step (under that step, which says what it unlocks: "Unlocks Messages, iPhone backup"), and the optional ones, with what you set aside with Not now. Its badge is orange while something needs you now (the Dock's and the menu bar's count only those), plain otherwise: how many haven't started. A source you skipped, or that isn't on this Mac, has no list of its own: it's in **All Sources**, under its kind (this Mac's and the iPhone's first), and opens there to include it again. **Setup Checks** (under This Mac) has its own to-dos: Full Disk Access, Python packages, the library out of iCloud, free space, and the settings that otherwise delete history (Messages, Safari, Claude Code, Terminal, Google, Maps Timeline). Only a check that holds the rest up (Full Disk Access, Python, the library in iCloud) needs you.
- **All Sources** (under Sources, beside Found in Your Data): the hub. Every service the app can collect from, about 2,700, by kind (social, shopping, money, travel...), searchable, so nobody has to remember what they signed up for. The built-in accounts are in it with their status; one click adds any other.
- **Found in Your Data**: the hub narrowed to services your mail (who emails you from account and notification addresses), the sites you visit and the apps on your iPhone and Mac point to, strongest evidence first, plus senders no directory knows.
- **Settings**: three pages, and every setting has one home. **General** (`src/renderer/general.tsx`): reading this Mac, watching Downloads, Mail and notifications for exports coming home, notifications, working when the window is closed, and the library. **AI Settings** (`src/renderer/ai.tsx`): whether AI is used, the agent and its sign-in or key, and Do It for Me (on or off, the browser it works in, how many sites it works on at once, downloading when an export is ready, checking every few hours, and the inboxes Claude may look in). The agent picked is for everything AI does; Do It for Me runs only with Claude Code and a claude.ai account (`agentProvider` in `src/shared/setup.ts`), so with Codex it says it's coming (`src/renderer/agent_gate.tsx`), and before Claude works in the browser it waits for Anthropic's data settings to be confirmed, as Ask does (what runs on its own needs them confirmed once). **Open at login** is for the installed app only: run from Terminal, it would add Electron itself to the login items.
- **Your Setup** (under Settings): what the app found on this Mac and uses, each changeable (`src/renderer/your_setup.tsx`; the defaults are `src/shared/setup.ts`). Who you are and the region phone numbers without a country code are read in (`connectors/phones.py`, this Mac's region unless picked); each browser found (`connectors/browsers.py`: installed, or with history here) with a switch for reading its history, and the browser export pages open in; and Mail's accounts. The browser Do It for Me works in starts as the default if Claude in Chrome runs in it, else the first of Chrome, Edge, Brave, Arc, Vivaldi, Opera (picked in AI Settings). The connectors hear of it through the environment (`setupEnv`): `UMP_BROWSERS_SKIP`, `UMP_PHONE_REGION`, `UMP_READY_MAIL=0`, `UMP_READY_NOTIFICATIONS=0`. Changing a browser's switch reads browsing history again; changing the region reads Messages and calls again. With several devices backed up here, "Your iPhone" picks whose backup is read (`phoneDevice` in `src/shared/status.ts`: the one picked, else the one read before, else the newest iPhone's); one read before that isn't yours can be taken out (`bridge.py forget-phone`: the phone's own sources, its copies in Messages and calls, and the decrypted copy), and the decrypted copy starts over whenever the device changes.
- **Ask**: questions about your own data, answered by a model you pick, with the records it used cited (see below).
- **Explore**: things assembled from your data on this Mac, with no model and nothing sent anywhere (see below).
- **Export Your Library** (General, by Your library; or the app menu, ⇧⌘E): the library in one .zip, saved where the save dialog says. Your records always go in: `corpus.db`, a file per source (`normalized/`), the stream, the manifest and who you are. Photos and attachments (`media/`) and the downloads as they came (`imports/`, `raw/`) can be left out; each shows its size, with about what the .zip will take and what's free. Anything else in the folder, and links out of it like `raw/iphone` (the decrypted iPhone backup), is left out. Imports wait while it copies, so nothing changes part-way; Stop leaves nothing behind (`py/export_library.py`, `src/main/library_export.ts`).

## Ask

Conversations on the left, the chosen one on the right, like Messages. The assistant answers as your assistant ("you"), looks things up with five tools, shows each lookup and how long it took, and cites records as links that open the record: a message in its conversation, drawn as Messages draws it (the days around it, scrolled to it and marked, its details and its page in Explore a click away), a calendar event as Calendar shows one, anything else by itself. What a citation opens is read from the library on this Mac; nothing more goes to the AI.

- **Who does the work**: one of two agent harnesses, the Claude Code or Codex CLI on this Mac, signed in one of these ways (one list, on AI Settings and in Ask's sheet, with what the choice picked needs right under it: its key, its model, the local server):
  - Claude Code with your claude.ai account, or with an Anthropic API key (`claude --bare`: only the key, none of your claude.ai login, hooks, plugins or CLAUDE.md).
  - Codex with your ChatGPT account, with an OpenAI API key (`CODEX_API_KEY`), or on a local model (`codex --oss` with Ollama or LM Studio; `gpt-oss` works best). With a key or a local model Codex gets a settings folder of its own in its run folder, so your ChatGPT sign-in is neither used nor changed.

  Keys are encrypted with the Keychain (Electron's `safeStorage`) and handed only to the process that needs them. Claude Code streams the answer as it's written; Codex sends whole messages. Their thinking shows above the lookups as it comes, open while they work and folded into one line once the answer starts: Claude Code's as a summary, asked for with `--thinking-display=summarized` (the API leaves it out otherwise; a Claude Code too old for the option is asked again without it), Codex's as its reasoning summaries. It's kept with the conversation, and never sent back with the next question. Neither CLI's telemetry is on (`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, Codex's `analytics.enabled=false`).
- **Ready before it's asked**: a question waits until the agent picked can answer: it's on this Mac, its key is saved, and (a local model) something answers at its address, which must be on this Mac (the app asks its `/models`, on localhost only). The box says what's missing and fixes it in place. An agent's own error comes back in plain words with what to do (sign in in Terminal, check the key, open Ollama), its raw words under Details, and Try Again asks the question again in its place; a failed or stopped turn is never sent back to the agent as an earlier answer.
- **Tools** (`py/ask_tools.py`): `sql` (read-only, with `local_time`, `regexp`, `median`), `search` (full text with filters), `python` (in a macOS sandbox: no network, no other program or child process, no Apple Events, nothing of the home folder, other users or other disks but the records, and it writes only a scratch folder of its own, deleted afterwards; what it prints is blanked of secrets again as a whole), `read_file` and `view_image` (the file a record points to: a document's original, a photo, a still from a video). Text results are blanked of secrets (`connectors/redact.py`) before any model sees them; photos are sent as they are. The database comes first because it's faster: on six test questions, an agent with it answered in 3.6 minutes in all against 8.6 reading the files.
- **Shown, not only cited** (`src/renderer/embeds.tsx`): on a line of its own, an answer can name something for the app to draw from the library, the way the app's other pages draw it: `[[chat:…]]` a stretch of a conversation, `[[photos:…]]` photos, `[[map:…]]` where records were or everywhere you were some days (the app's own coastlines: nothing fetched), `[[day:…]]` a day as Your Stream has it, `[[trend:…]]` a count month by month (messages with someone, songs by an artist, visits to a site, steps, sleep…), `[[person:…]]` someone in Your People, `[[email:…]]`, `[[songs:…]]`, `[[trip:…]]`, `[[agenda:…]]` calendar events, and `[[they-know:…]]` what a service decided about you. The answer names them by rowid, date or name (`src/shared/markdown.ts`); `py/explore.py embed` reads them from `corpus.db`, so the model never sees more than it looked up. Each opens what it shows: a record, a conversation, or its page in Explore.
- **Every lookup runs in the app.** Claude Code runs with its own tools off and hooks off, from a folder of its own under the app's data (never the shared temp folder, where a CLAUDE.md could be left for it), in a sandbox that can't read the corpus, the app's data, the Mac's own data (Messages, Mail, Photos, other apps', the decrypted iPhone backup), keys or other disks, and reaches the tools through an MCP server. Do It for Me runs in the same sandbox, without the browser's JavaScript tool, from the same folder for each service every time (emptied as it starts: Claude Code keeps a session by the folder it ran in, so Continue has to run from there), and opens a ready email's link only when it's under the service's own export pages (`src/shared/agent_link.ts`); an email that only names the service, or sits in Junk, is a guess with no link. Codex always has a shell, so it runs under a Codex permission profile that closes the home folder (the app's Full Disk Access would otherwise pass to it) and the network; it looks things up with `./ask` in its run folder. Both CLI agents hand each call to the app through a mailbox folder in their run folder, since their sandboxes can't open sockets.
- **Keeping your data out of training**: before a cloud provider's first use, and again every 90 days, a sheet says what that company keeps and which setting keeps it least ("Help improve Claude" off, ChatGPT's "Improve the model for everyone" off, the API's retention period), and the question waits until you confirm. A line under the composer keeps the reminder in view.
- Conversations are saved in the app's data folder (`ask/<id>.json`); nothing is saved by the CLIs (`--no-session-persistence`, `--ephemeral`), so the corpus doesn't read your questions back in as your own prompts.

## The event stream

`connectors/stream.py` turns `corpus.db` into what happened, in order, one local month at a time, and writes it to `corpus/stream/YYYY-MM.jsonl` (one event per line; `months.json` says how many each holds). `build_index.py` runs it after every rebuild, for the months whose records changed, so the files stay current; `python3 connectors/stream.py build --all` rewrites every month, and `month YYYY-MM` prints one. The Your Stream page shows the same events; Ask's python tool reads them with `stream('2026-09')`.

- **Left out**, because they aren't something you did or that happened to you: device bookkeeping from the iPhone backup (its file index, Wi-Fi, app state, permissions), raw Health samples (the day totals and nights of sleep stay), spam and deleted mail, ads you were shown, Screen Time day totals and glances at an app under 2 minutes, iOS's index of whom you contacted (the messages and calls themselves stay), and X's bookkeeping for direct messages.
- **One thing, once**: a page seen by Chrome, Chrome Sync and Google's My Activity; a search in the browser and in My Activity; an event in several calendars; a note, reminder or voice memo on the Mac and the iPhone. The copy closest to where it happened is shown; every copy is kept in the event's `refs`.
- **A run is one event**: messages in one chat until a 45-minute pause; pages and searches on one device until a 10-minute pause; photos until 45 minutes; one app on one device until it's left alone for 10 minutes; YouTube, music and maps until 30 or 15 minutes; commits to one project until 2 hours; an AI session until 45 minutes. Newsletters and notifications are one event a day per mailbox (a Gmail category other than Primary, an automated sender, or "unsubscribe" in it).
- **When data is missing or odd**: an app's data can be absent, partial or shaped in a way no rule expects (a number written as text, a field missing, metadata that isn't an object, a time with no zone). The stream never fails because of it: numbers are read leniently, and a record no rule can describe still becomes a plain event ("N things in App"). Events are ordered by when they happened, whatever zone each is written in. `connectors/tests/test_stream.py` checks every test record in many broken versions, and each app's records on their own.
- **An event**: `start` and `end` (local wall-clock time with its offset; photos and Health keep their own zone), `kind`, `app`, `device`, `title` (one line, plain words), `lines` (the first messages, the sites, the queries, the tracks), `people`, `count` (records in it), `mine` (how many were yours), `refs` (`"source:id"` of every record, which, unlike rowids, survive a rebuild), and `all_day` for a day's totals.

## Explore

Fourteen artifacts, each a tile on the Explore page that opens in place, built by `py/explore.py` from `corpus.db` (read-only) and kept until the database changes (in the app's data folder, `explore-cache/`, and in memory while the app runs). They're built ahead, without waiting for Explore to be opened: a few seconds after the app starts with a library, and again after each read or import that changes it, once nothing else is being read. Opening Explore then shows them at once; anything opened while they're still being built goes ahead of the rest, or joins the one being built. Anything that came from a record opens it, in Ask's record sheet.

- **On This Day**: today's date (or any day) in every year of your data: photos, who you talked to, calls, searches, YouTube, what you made and planned, your steps.
- **Your People**: everyone you've talked to one on one (Messages, Instagram, Messenger, Discord, WhatsApp, calls), your ten closest each year, and a page per person: messages by month and hour, who starts conversations (not counted where an export keeps only your side), calls, photos together, busiest days. A name ending in an initial ("Grace H") joins the only matching full name; Photos' first-name tags join the only person you talk to with that first name.
- **Places and Trips**: where your photos were taken, on a map drawn from bundled coastlines (`data/world_land.json`, Natural Earth), and trips: stretches of days whose photos are more than 100 km from where you took photos on the most days in the 90 days around (so home moves when you do).
- **Your Rhythms**: messages, browsing, searches, YouTube, code and photos by weekday and hour, when your busy days wind down each year, steps by weekday. Times are this Mac's zone, or a record's own (photos, Health).
- **Firsts**: your first message with each person, first photo in each place and country, first commit to each project, and the earliest record from each app (a first is as early as your data goes back).
- **What You Made**: a calendar of the days you committed code, wrote, posted, worked with an AI or took photos, with streaks and totals by year.
- **Your Year**: a year as a story, played a slide at a time like Replay or Memories: your people and who was new, messages by app, distance and flights, trips, a photo from each month, what you made, your busiest hour, steps, firsts and your biggest day; then every number at once. Any year with data, the latest by default.
- **Journeys**: every move of more than 150 km between places you were, drawn as great-circle arcs on a dark map that turns to put its seam where the fewest arcs cross. A move is a flight when nothing on the ground is that fast (250 km/h over the whole gap, or 2,500 km within three days); totals by year, countries in the order you first went, and where your days were.
- **Group Chats**: every conversation with two or more others, from any app: who talks, superlatives (talks most, night owl, most emoji, writes the longest), when it was alive, and its own words: ones two or more of you use often and far more there than in your other chats.
- **Listening**: every song played, from Spotify's streaming history, the Mac's Now Playing (music apps only) and YouTube's artist channels ("Artist - Topic"): top artists and songs, all time and by year, your eras (the artist you played most, season by season), songs on repeat in a day, and when you listen. A Spotify play counts from 30 seconds, as Spotify counts it.
- **Moving and Sleep**: Health's steps by month and weekday, your biggest days (and where you were, from that day's photos), days over 10,000 and the longest streak of them, steps on trips against at home; with a sleep tracker, nights by year, bedtimes and how long you sleep by night of the week.
- **Curiosity**: every search, once (the same words in Chrome and Google within the minute count once; searches inside Gmail and the Play Store aren't counted), from Google's My Activity, Safari and Chrome: each year's own topics (words and phrases searched far more that year than in others; a phrase over the words in it), the questions you asked, what you searched again and again, and what you looked up in the weeks before each trip (by every place name the trip's photos give it).
- **Watching**: YouTube (artist channels are songs, in Listening), Netflix on the iPhone, TikTok and video apps the Mac was playing: most-watched channels and shows (episodes count for their show), what you watched again, your longest evenings, how much after midnight.
- **Your Stream**: a month as it happened, every event in order, day by day: conversations, calls, mail, browsing and searches, what you watched and listened to, photos, calendar, notes, code and AI sessions, app use, social activity, Health. Built by `connectors/stream.py` (above). Filter by kind, search the month, jump to a day; open an event for all of it and every record in it. The latest month by default.

A tile without enough to show is locked: greyed, with what it needs and where that comes from ("Needs your listening history: from Spotify, or YouTube in Google Takeout"). It opens to what it would show and the sources that bring it, each with its status and a button to it. The rules are `NEEDS` in `src/renderer/explore.tsx`: Listening wants 50 plays, Curiosity 50 searches, Watching 30 videos, Moving and Sleep two weeks of Health (sleep its own two weeks), and the others something to show at all.

These work from what records are, not which app made them, so they hold for anyone's data: a group is a conversation an app flags as one, or with two or more others in its participants or among its writers (one an export keeps only your side of is left out); a place you were is any photo, video, check-in or location record with coordinates, except a picture saved from a messaging or social app (it carries someone else's location), a photo others shared with you (shared albums, Shared with You, iCloud links, what others added to a Shared Library: `photos.py` keeps those as `shared_photos`) and a point nothing could have reached in time; an app's name comes from what its records say they came from. Lines an app writes itself ("Grace sent an attachment.") are told apart from what people wrote by being word for word the same from three or more people once their names are taken out.

The look follows Apple's summary screens (Photos Memories, Health, Fitness): a bento of tiles, each showing its artifact as a picture (the day's photos, your closest people, a map, a heatmap, a calendar) and one big number, and on each page a hero card in the artifact's color, people as monograms, countries as flags, trips as photo cards. A tile zooms into its page's hero and back (a view transition, `animate(…, 'zoom')`), deeper pages push in from the side, numbers count up, and charts grow in on a spring sampled from a damped spring; Reduce Motion turns all of it off.

A message opens its conversation, the way Messages shows it: both sides of that day's exchange and a little either side, with earlier and later a click away (`explore.py thread`). While an artifact is still being built (opened before it was built ahead), its page shows a ring that fills as its steps finish (`explore.py` reports progress on stderr; `src/main/explore.ts` forwards it), and the tiles fill in one at a time.

Thumbnails come from the record's file or, for photos, Photos' own previews on this Mac (they exist even when the original is only in iCloud). Charts use one blue for single series and a five-step blue for heatmaps, checked for contrast against the window in light and dark mode; each has hover details and a list or table beside it.

## How each kind of source works

| Group | What the app does | What you do |
|---|---|---|
| On this Mac | Reads every present source as soon as it knows who you are, then again whenever a source is a day old while the app is open (Screen Time, Chrome and the call log forget history) | Grant Full Disk Access |
| iPhone backup | Finds Finder backups, notices newer ones, runs `connectors/iphone.py` (decrypt + iLEAPP) | Type the backup password. It's piped to the decryption step and never saved or logged |
| Web exports | Opens the export page in your own browser (signed in already, with your passwords) with the steps in the app, or with **Do It for Me** has Claude Code request it in your browser, Chrome or the one picked in AI Settings (`src/main/export_agent.ts`: `claude -p --chrome` with only the browser tools, the service's steps as its instructions, stopping for sign-ins and codes and carrying on in the same session on Continue). **Ask for Everything** first checks which services the browser it works in is signed in to (`py/signins.py`: each session cookie's site, name and expiry, read in place, never its value), runs Claude through them a few at once (3 unless set otherwise in AI Settings, 1 to 5: `src/main/agent_pool.ts`, each run a Claude Code session with a tab group of its own, never two on one service; downloads go first, and a usage limit or the extension gone in one stops the rest) with one notification at the end (one waiting for you in the browser is said at once), and carries on by itself once a sign-in it stopped for is done. Tracks when you requested it, looks in Apple Mail's index for the service's "your data is ready" email (and takes its download link from the message) and in this Mac's notifications (a guess, shown as "looks ready"; forward the iPhone's notifications to the Mac and those count too), downloads it with Claude once it's ready if you let it (and has Claude look for it every few hours, a setting of its own; Stop Checking turns that off for one service), reminds you when it should be ready and before the link expires, picks the download up from Downloads, files it in `corpus/imports/<source>/` and imports it | Sign in, pick the options, say "I've requested it", or sign in when Do It for Me asks |
| Guided | Shows the steps and watches Downloads for the file (Maps Timeline, mailbox exports, vCards, WhatsApp chats, Slack, Zoom) | The steps on your phone or in Mail |
| Other services | Any service you add, by hand or from Found in Your Data, with its export page when a directory knows it, or a drafted GDPR/CCPA access request when it doesn't. Whatever its download holds is kept, in any format | Request it, drop the download |

Downloads are recognized by their contents, not their names (`py/bridge.py identify`), so renamed files, `.zip.zip`, unzipped folders and multi-part Takeouts all land in the right place. An export you were expecting is imported on arrival; anything else waits for a yes. Files on another volume are copied, never moved (under a `.partial` name until the copy is whole). A download still being written (`.crdownload`, `.part` and Firefox's empty file beside it, Safari's `.download`) waits until it's done; one locked with a password or packed in a way Python can't unpack (Windows' Deflate64) asks to be unzipped in Finder first; an empty or cut-short one asks for the download again; the same file dropped twice is left where it is. Zips made on a Mac or on Windows, zips in zips, zip64 and zip bombs are handled as `connectors/PARSERS.md` says. A mailbox goes in a folder named after its account, never another source's (`src/shared/status.ts mailSource`: one named Mail goes in `mail_mail/`, so it can't replace what Mail on this Mac read).

Every import runs each `imports.py` parser on its own (`bridge.resilient_imports`), so one malformed export marks only its own row as failed instead of blocking every other import, and the sources a failing parser was writing keep their previous records rather than a half-read version. Export files that iCloud's "Optimize Mac Storage" has moved to the cloud are downloaded before parsing (`brctl download`); reading a 2 GB mailbox on demand can time out partway. That function mirrors `imports.main()`; `test_bridge.py` fails if the two drift apart.

## Services the app doesn't know

The long tail (a writing site, a gym, a forum) is handled without a parser per service:

1. **Every service is listed** in the hub, by kind (`data/categories.json`, sorted once by Claude from each service's name and domains), so finding yours is recognition, not recall.
2. **Which services you use** comes from evidence, not memory: `bridge.py discover-services` matches mail senders, visited sites and installed apps against `data/services.json`, about 2,650 services built by `scripts/build_services.py` from two MIT-licensed directories (JustDeleteMe for names and domains, JustGetMyData for export steps; notices in `data/THIRD_PARTY.md`). `--check-links` drops export pages and services that no longer exist (`data/link_check.json`); `npm run icons` matches them to brand logos from Simple Icons (`data/service_icons.json`); a unit test checks that every service opens its export page, else its home page, never a page for deleting the account. Senders no directory knows are listed too, by the name they go by.
3. **Nothing is lost**: a service you add files its download in `corpus/imports/<folder>/`, and `imports.py`'s catch-alls keep every JSON/CSV item, document and media file, with times when one is found.
4. **Structure comes after**: Claude reads the download's structure (file names, field names, kinds of values; one example value per field only if you tick it) and writes a mapping, which is data, never code: which files hold posts or comments, and which fields are the time, text and author. `bridge.py try-mapping` runs it over the whole download for a preview; once you use it, `connectors/mapped_exports.py` reads that folder with it before the catch-alls. The request goes to the agent Ask uses, signed in the same way (account, key or local model), with no tools, once that provider's data settings are confirmed; with AI off, asking goes through the one-time AI agreement. Without an agent, copy what's sent into any AI chat and paste the reply back.
5. **The next person starts with it**: tick "Add it to the app's mapping library" and the mapping goes to `data/mappings/<service>.json`; anyone who adds that service later starts with it.

## Layout

```
src/shared/catalog.ts   every source: group, steps, URLs, wait and expiry, what it produces; services you add
src/shared/contents.ts  what a source holds, in words; src/shared/phone.ts: every iPhone source, described
src/shared/hub.ts       the hub: built-ins, services you added and the directory, each once, by kind
src/shared/status.ts    pure: probe + stats + saved state + jobs -> one view per source
src/main/main.ts        window, IPC, actions, downloads, reminders, daily refresh
src/shared/setup.ts     Your Setup: the browser Do It for Me works in, whether it can run, what the connectors are told
src/main/jobs.ts        one connector run at a time (they share manifest.json and corpus.db)
src/main/agent_pool.ts  Do It for Me's runs: a few at once (src/shared/at_once.ts), the rest waiting their turn
src/main/downloads.ts   Downloads watcher, where files go, moving them
src/shared/version.ts   which version this is, and what's new in it (../CHANGELOG.md); src/renderer/whats_new.tsx shows it
src/renderer/app.tsx    the interface; src/renderer/welcome.tsx, the welcome page (examples.ts, its made-up data)
src/main/ask.ts         Ask: the providers, the tool workers and mailbox, conversations, keys
src/shared/ask.ts       Ask: providers, what each keeps of your data, the events of an answer
src/renderer/ask.tsx    the Ask page; src/shared/markdown.ts parses the answers
py/bridge.py            the app's only way into the connectors; prints JSON
py/ask_tools.py         Ask's tools over the corpus; py/ask_prompt.md, the assistant's instructions
../connectors/stream.py the event stream: corpus.db as events in order, a month at a time, into corpus/stream/
```

## Tests

```bash
npm test             # all three suites below
npm run test:unit    # status logic, queue, downloads, catalog cross-checks; Ask against fake providers and CLIs
npm run test:py      # bridge.py: probe, identify, stats, real connectors in a sandbox; Ask's tools and their sandbox
npm run test:e2e     # the real app driven by Playwright
npm run test:clis    # Ask: the real Claude Code and Codex CLIs, signed in with a key, against stand-in model servers
npm run test:real    # this Mac's real data (below); run it before every release
```

The end-to-end tests launch the app against a sandbox: a fake `HOME` (Claude Code sessions, a git repo, a fake encrypted backup), a throwaway corpus, a fake Downloads folder, and a local site standing in for the export pages. The real `imports.py` parses fixture exports for every format. `real_data.test.ts` also runs on this Mac's real data: read-only over the real corpus (checked byte for byte afterwards), and the real Mac connectors reading the real Library into a temporary corpus. `walk_real.test.ts` goes through the Setup Assistant from the welcome page to the end as a new person would, on the real Mac, into a throwaway corpus it deletes afterwards. It then waits for Explore, and fails if the app or anything it starts connects to anything but this Mac. `recovery.test.ts` kills the app in the middle of a read and checks that the next launch finishes it. Screenshots land in `test-results/`.

**Installing:** `npm run install-app` builds `Homecoming.app` for Apple silicon and puts it in Applications (`scripts/install_app.mjs`, building with `scripts/package_mac.mjs --app`). Built on the Mac it runs on, it isn't marked as downloaded, so macOS opens it without asking. `npm run package` builds `release/Homecoming.app` and a `.dmg` of it; the `.dmg` isn't offered to people, since unsigned, macOS warns about it. The app holds the built interface, `py/` and `data/` in `Resources/app`, `connectors/` (vendored iLEAPP and its wheels included) in `Resources/connectors`, and its own Python 3.14 in `Resources/python`, with cryptography and pypdf installed and everything compiled ahead of time. So nothing is installed or downloaded when it runs, and it never writes into itself (`PYTHONDONTWRITEBYTECODE`). Packaged, the library is `~/Homecoming` and Full Disk Access goes to Homecoming itself. The two downloads the build makes (a [python-build-standalone](https://github.com/astral-sh/python-build-standalone) build and pypdf's wheel) are pinned by SHA-256. Electron is the copy `npm ci` installed. Electron's fuses for running as plain Node, `NODE_OPTIONS` and `--inspect` are turned off, and the installed app ignores the test settings below (`src/main/env_guard.ts`), so no other program can borrow its Full Disk Access. `node scripts/package_mac.mjs --app --test-hooks` builds one that keeps them, and `UMP_APP=release/Homecoming.app/Contents/MacOS/Homecoming npm run test:e2e` runs the end-to-end tests against it. `npm run icon` redraws `build/icon.icns` from `build/icon.svg`.

**Versions:** `package.json`'s version is the release's, shown in About Homecoming and at the bottom of General with the commit and the day it was built (`build.mjs` writes them into `dist/build.json`, and copies `../CHANGELOG.md` into `dist/`). Each version has its section at the top of `CHANGELOG.md`, in plain words; the first launch after an update shows what's new since the version that ran before, once (`state.json` `lastVersion`; a library from before versions were kept gets the current version's, a new one nothing). A unit test checks that the changelog's newest section is `package.json`'s version. Until a version is published, a change people will notice adds a line to its section; the first change after it's published raises the version (the last number for fixes, the middle one for something new) and starts the next section.

**Updating:** once a day (unless General → Updates is off), and on Check for Updates…, the app fetches the public repository's `CHANGELOG.md` from raw.githubusercontent.com: one plain GET, nothing sent, silent if it fails (`src/main/updates.ts`). Besides Claude, it is the one request the app makes by itself. A newer version is said once in a notification, then stays as a card at the bottom of the sidebar, opening its sheet (`src/renderer/update_sheet.tsx`). Nothing installs by itself. **Update** runs `scripts/update_app.mjs --status … --open` from the clone the app was built from (`build.json` `from`), on its own, so it outlives the app. It does `git pull --ff-only`, `npm ci`, then `install_app.mjs`, each only if the one before worked. `install_app.mjs` quits the app with SIGTERM (as Quit does: no permission to control another app is needed) and opens the new one. The sheet shows where it is and, if it stops, why, in the script's words. Only the installed app built from a clone of the public repository has Update. Run from Terminal, downloaded as a ZIP, or built from another folder, the sheet says what to do instead. Testers who'd rather use Terminal run `npm run update`. A file they changed, or a commit of their own, stops it before anything is pulled, with what to do; it never resets or overwrites them. Once it has pulled, the new copy of the script does the rest, so a fix to updating works straight away. `--no-install` updates the code and its packages only, for running from source. The demo, read-only mode and every hidden run (the tests) never look.

**Releasing:** `python3 desktop/scripts/publish_release.py` gets a version ready for the public repository and stops before the push. From a clean worktree of private main (fetched), `release_copy.py` makes the release copy (the app, `README.md`, `WHAT_TO_TRY.md` and `CHANGELOG.md`, nothing else, and never the demo) and checks it for personal data against the corpus. It goes over a fresh clone of the public repository, but first, what was merged or edited there since its last release (community pull requests, an edit on GitHub) must be in private main, or the copy would undo it: brought over with `git cherry-pick -x`, which names it, or by hand, or left out on purpose with `--skip-public SHA`. Otherwise it stops and lists those commits. The version must be newer than the public one, with its section in `CHANGELOG.md`; the clone's tests run (`--quick`: unit and Python only); and it's committed as `Homecoming 0.3.0`, a blank line, then that section's bullets. Then it prints the commit and the `git push` that publishes it. Never force-push the public repository: every tester's `npm run update` is a `git pull --ff-only`.

Environment variables used by the tests (and handy for trying things safely): `UMP_READONLY=1` (never move files, run connectors or save a setting, other than turning AI on for Ask), `UMP_NO_AUTORUN=1`, `UMP_WHATS_NEW=1` (show What's New after an update in a hidden run, which otherwise skips it), `UMP_UPDATE_URL` (where to look for a newer version; a hidden run looks only when it's set) and `UMP_UPDATE_SOURCE` (the clone Update updates, as if the app were installed from it), `UMP_EXPLORE_WARM` (`1` or `0`: build Explore ahead or not; the tests leave it off unless they ask, and `UMP_EXPLORE_WARM_MS` sets how long after the app goes quiet it starts), `UMP_USER_DATA`, `UMP_DOWNLOADS`, `UMP_PYTHON`, `UMP_URLS` (JSON `{sourceId: url}`), `UMP_IPHONE_MODULE`, `UMP_EXTERNAL_LOG` (write links and mail drafts to a file instead of opening them), `UMP_APPLICATIONS` (where to look for Mac apps), `UMP_CLAUDE_CMD` (the Claude Code CLI, for mappings and Ask), `UMP_CODEX_CMD`, `UMP_ANTHROPIC_URL` and `UMP_OPENAI_URL` (where Claude Code and Codex reach the API when signed in with a key), `UMP_ASK_ANTHROPIC_KEY` and `UMP_ASK_OPENAI_KEY` (keys that skip the Keychain), `UMP_SIGNAL_KEY` (the same, for Signal's database), `UMP_MAPPING_LIBRARY`, and the settings' own (`UMP_BROWSERS_SKIP`, `UMP_PHONE_REGION`, `UMP_READY_MAIL`, `UMP_READY_NOTIFICATIONS`), which the app sets from Your Setup and General. `test/fakes/` has the stand-ins: a streaming Anthropic API and a local model server, and fake Claude Code and Codex CLIs that call the real tools.

## Not done yet

- **Signing.** The app is signed ad hoc, so it's built on each Mac rather than downloaded. A Developer ID signature and notarization would let it be offered as a download.
- **Run from source, it works only while it's open.** The installed app keeps working in the menu bar and opens at login (General).
- **Do It for Me stops for sign-ins and codes.** It works in your own browser (an app's built-in browser can't sign in with Google, and loses your saved logins and passwords), so a service that asks you to sign in, enter a code or prove you're not a robot waits for you.

### Library locations

Files copied into the library (attachments, media from exports) are recorded relative to the library, such as `media/whatsapp_export/photo.jpg`, so they're found wherever the library is, packaged or renamed. References written before, prefixed with `corpus/` or the library's old name, still resolve, and Ask keeps its checks that a record's file stays inside the library (or its link to the decrypted iPhone mirror).

Photos is read from every `.photoslibrary` in `~/Pictures` and from the system library Photos records (`photolibraryd`'s preference), including one on an external drive; `UMP_PHOTOS_LIBRARY` picks one. The setup check and the importer look in the same places. Git repositories are found in worktrees too (a `.git` file), and a commit is yours by your exact address, name or username, including GitHub's private address.

### Who's one person

Explore's People, On This Day, trips and Firsts count a person once, wherever you talked. Messages, calls and WhatsApp name people as your Contacts do, so one name there is one person, with all their numbers and addresses. Instagram, Messenger and Discord show the names people gave themselves, so two conversations in one of them with the same name (two accounts called "Oren Halvorsen", or the "Instagram User" of every deleted account) stay two people. Otherwise a full name joins the same name in your other apps, and a first name alone ("Alex") joins only the contact you saved by exactly that name. "Ada L" still joins the one "Ada Lovelace". A connector that knows for certain who a conversation is with can say so with `meta.person_id`.

A number saved without its country code still finds its contact by its last nine digits, but only when one number in your contacts ends that way. Times from 1900 on count (a scanned photo from 1985); a clock's first second (1900, 1970 or 2001 at midnight, a missing time read as 0) doesn't.
